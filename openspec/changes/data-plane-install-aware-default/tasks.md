## Follow-up (out of scope for this change)

- Terminal I/O through the panel's `TerminalBridge` is less reliable than the daemon's direct socket path: `streams.test.ts`'s "disconnect s1 → s2 still receives" and `docker.test.ts`'s container terminal round-trip both fail in `proxy` mode but pass in `direct` mode, while `dataplane.test.ts`'s proxy terminal case (dual-socket broadcast + Chinese + stop) passes. This change keeps its "mode-dependent behavior is unchanged" boundary by pinning the affected suites to `direct` (D7), but the flip makes the bridge the default for every new install, so the gap should be tracked and fixed separately (reproduce the two failures with `dataPlane=proxy`, then decide whether `TerminalBridge` needs per-subscriber stream clients or a different refcount/teardown path).
